# 공정 디지털 트윈 — 명세 `#2-6` 모델링 구현

황산 침출 공정을 가상 공간에 세우고, 모듈 1·2·3 이 추천한 레시피를
그대로 운전 조건으로 받는 3D 씬이다.

## 여는 법

정적 페이지라 파이썬 없이 열린다. 다만 **파일을 더블클릭하면 빈 화면이 뜬다** —
브라우저가 `file://` 에서 ES 모듈과 `fetch()` 를 막기 때문이다. 서버를 거쳐야 한다.

```bash
python -m http.server 8000 --directory docs
# http://localhost:8000/modeling/
```

GitHub Pages 를 켜면(Settings → Pages → `main` / `docs`) 주소 하나로 열린다.
파이썬 모델이 실제로 도는 쪽을 보려면 `docker compose up --build` 후
<http://localhost:8501>.

## 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 페이지 — 레이아웃·팔레트·제어 UI |
| `scene.js` | 씬 구성, 애니메이션 3종, 모델 계산, 격자 탐색 |
| `data.json` | 모델 계수 · 적용 범위 학습점 · 표본 배치 · σ 격자 **(생성물, 커밋함)** |
| `export_data.py` | 파이프라인에서 `data.json` 을 다시 만든다 |
| `standalone.html` | 전부 인라인한 단일 파일 **(생성물, 커밋 안 함)** |
| `build_standalone.py` | `standalone.html` 을 만든다 |

`data.json` 과 `standalone.html` 은 손으로 고치지 않는다. 모델을 다시 학습했으면:

```bash
python docs/modeling/export_data.py        # data.json 갱신
python docs/modeling/build_standalone.py   # standalone.html 갱신
```

`data.json` 을 커밋하는 이유는 `artifacts/` 와 `data/processed/` 가 `.gitignore`
대상이라, 클론만 한 사람에게는 이것을 만들 재료가 없기 때문이다.

## 명세 최소 조건

페이지 상단 띠의 숫자는 **씬 그래프를 실제로 순회해 센 값**이다.
치수는 `Box3().setFromObject(room)` 바운딩 박스 실측이고,
수량은 `userData.spec` 태그(`map` / `facility` / `ore`)를 센다.

| 조건 | 구현 |
|---|---|
| 공장 25m × 17m × 6m | 25.0 × 17.0 × 6.0 (실측) |
| 맵 1개 | 공장 내부 — 바닥 줄눈, 천장 트러스 6연, 파이프 랙, 조명 3기 |
| 설비 1개 | 침출 반응조 R-101 — 원뿔 하부·동체·돔 헤드·2단 임펠러·배관·발판 |
| 애니메이션 3개 | 교반기 회전 / 원료 이송·투입 / 황산 주입·승온 |
| 광석 3개 | A·B·C급 블랙파우더 호퍼 |

## 조작

- 드래그로 회전, 휠·핀치로 확대
- 우상단 **전경 · 반응조 · 투입부 · 평면도** 시점 버튼
- 뷰포트 아래 체크박스 3개로 애니메이션 개별 토글
- 좌측 **모듈 3 추천 레시피 적용** — 파이썬이 미리 구한 해로 이동 (즉시)
- 슬라이더로 다른 조건을 고르면 회수율 평균 · 산 비율 · 적용 범위 거리만 보여 준다. 비율이나 적용 범위를 벗어나면 「거절」, 그 밖은 「참고」로 표시하고 목표 달성 여부는 판정하지 않는다.

원료 목록의 `✓` 는 기본 목표(Ni 95% · Co 90%) 기준으로 허용 범위 안에 목표 달성 조건이 있는 배치,
`✕` 는 없는 배치다. 대부분이 `✕` 인 것은 정상이다 —
원본 420건 중 Ni≥95 와 Co≥90 을 동시에 만족한 실측은 6건뿐이다.

이 판정과 추천 레시피는 `export_data.py` 가 배치마다
`module3_optimization.recommend()` 를 호출해 구한 값이다. 브라우저는 표시만 한다.

## 한계

**목표 달성 판정은 파이썬 결과가 있는 조건에서만 한다.** 확률 제약에 쓰는 σ 는
트리 앙상블(rf·hgb)이 필요해 브라우저에서 정확히 계산할 수 없다. 한때 (온도 × 시간)
격자의 근사 σ 로 판정했더니 파이썬과 어긋났다 — 격자 탐색은 달성 가능 7/54 (실제 2/54),
슬라이더 즉석 판정은 실제로는 미달인 배치 5개에서 「운전 가능」을 띄웠다.
그래서 판정은 `data.json` 에 담긴 모듈 3 결과(✓/✕, 추천 조건)로만 표시한다.
54개 배치 × 슬라이더 조건 22만여 개를 검사해 파이썬과 어긋나는 판정이 0건임을 확인했다(11/18).

μ(회수율 평균)와 적용 범위 거리는 근사가 아니다. 파이썬과
소수점 넷째 자리까지 일치를 확인했다. `data.json` 의 σ 격자는 지금 화면에서 쓰지 않는다.

정확한 수치가 필요하면 Streamlit 데모를 쓴다 — 거기서는
`module3_optimization.recommend()` 가 그대로 돈다.
